# 早期菜单备选方案（历史存档）

2026-10-28 更新：用户已批准独立安装的 2.1 Beta，采用“首页／学习／班车／预约／校园”。以下 A/B/C 是此前讨论存档，不是当前实施方案；以 [2.1 Beta 发布记录](../RELEASE-2.1.0-beta.1.md) 为准。

原始讨论：以下是备选方案存档。用户已明确选择“先整理，不重构菜单”，当前仅执行共用组件、入口实现及缓存整理，B／C 不纳入本轮计划，现有底栏和菜单位置保持不变。

## 当前需要解决的结构问题

- 底栏混合了网站来源（门户）、任务领域（学习、预约、班车）和个人中心（我的），分类依据不同。
- 课表、作业、考试同时出现在学习与我的；可以保留摘要，但详情、排序和缓存应只维护一套。
- 班车偏好在页面上，作业提醒在学习设置中；页面操作与全局偏好的边界不清晰。
- 网页、原生详情、表单弹窗分别使用多套打开方式，同一入口容易产生不同返回路径。
- 目前设置层级已有语言、学习与课表、通用、隐私、网页、站点、存储等分组；下一轮应先明确分组职责，再决定是否改底栏。

## A：保留五栏，先整理重复入口

底栏：**班车 / 门户 / 学习 / 预约 / 我的**。

- 学习负责课程、课表、作业和考试的完整页面；我的保留可配置的摘要卡片，点击进入同一详情。
- 预约统一“查找场地”和“我的预约”，练习房／讨论室与体育保留独立分类。
- 我的保留消息、快捷入口、下载、设置；服务中心仍作为快捷入口。
- 所有根页使用原生大标题；右上角放当前页主操作及更多菜单。普通详情沿导航栈进入，独立确认任务使用弹窗。

优点：保留现有使用习惯，可以逐页交付。取舍：网站来源和任务分类仍然并列，门户与学习之间仍会有交叉。

## B：保留班车直达，把门户升级为“今日”

底栏：**班车 / 今日 / 学习 / 预约 / 我的**。

- 今日按时间呈现：当前／下一节课、待提交作业、未来预约、下一班车摘要；消息中心只保留实际需要处理的消息。
- Student 作为今日中的“校园入口”提供，同时把已提取的课程、考试放进学习。网页业务仍可以直接打开。
- 学习整合课程、课表、作业、考试，按任务进入，不要求用户先判断内容来自 Student 还是 Moodle。
- 我的收纳个人偏好、快捷入口、下载及设置。今日是日常总览，我的是个人管理。

优点：班车仍一键直达，整体更像校园助手；日常任务有明确起点。取舍：需要迁移门户路由、启动页和快捷入口，并明确“今日”与消息中心的不同职责。

**建议作为下一阶段的目标方案。先完成 A 的共用页面与路由整理，再分步替换门户为今日。**

## C：合并为四栏

底栏：**今日 / 学习 / 校园 / 我的**。

- 校园集中班车、场地预约、服务中心与校园网站。
- 今日保留常用场景的一键卡片，弥补部分功能进入层级加深。
- 学习和我的职责与 B 一致。

优点：顶层分类最清楚，后续新增校园服务容易归类。取舍：班车失去独立底栏入口；你目前频繁使用班车，这个变化需要先验证是否方便。

## 三种方案都建议采用的控件规则

| 层级 | 统一规则 |
| --- | --- |
| 根页面 | 原生大标题、随滚动收起；统一浅／深背景与内容边距 |
| 普通详情 | 导航栈进入、左上返回；保持所属底栏位置 |
| 预览与独立确认 | 弹窗呈现；只保留完成当前任务所需按钮 |
| 顶栏操作 | 主操作直接可见；次要操作进入更多；页面偏好不挤占正文 |
| 设置 | 全局偏好集中管理，页面菜单只放与当前任务有关的控制 |
| 消息 | 有事件才生成；空分类隐藏，调试信息留在 Beta 模式 |
| 数据 | 同一课程／作业／预约只有一套本地快照；先展示缓存，再后台更新 |

## 建议实施顺序

1. 统一页面外壳：标题、背景、边距、工具栏、返回与弹窗关闭规则。
2. 整理路由：同一功能从卡片、通知、快捷入口进入同一个页面；保留每个底栏的返回位置。
3. 合并重复详情与数据：学习／我的只共享摘要和详情，不再分别实现。
4. 调整设置分组：外观与语言、学习与提醒、班车与出行、网页与账号、文件与存储、隐私、关于。
5. 按 B 试做今日页，验证一屏能否看清下一节课、最近作业与预约，再迁移默认启动页。

本阶段仅更新班车外观，没有执行上述菜单重构。
