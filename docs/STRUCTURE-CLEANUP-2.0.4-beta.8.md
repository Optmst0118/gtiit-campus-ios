# 第一轮结构整理 · 2.0.4-beta.8

范围：共用组件、重复详情入口、缓存文件读写和详情返回状态。保留现有五个底栏、菜单分组、快捷入口及它们的位置，不实施“今日”或四栏方案。

## 共用部分

| 部分 | 统一实现 | 调用位置 |
| --- | --- | --- |
| 原生详情入口 | CampusDetailPage / CampusDetail | 我的摘要、学习全部作业、课表导入结果、设置下载、全局下载弹窗、校历快捷入口 |
| 详情页面外观 | nativeDetailSurface | 作业、考试、课表、校历、下载 |
| 作业文本 | MoodleWorkText，保留详细／紧凑两种密度 | 我的摘要、作业列表、Moodle 首页卡片 |
| 临近作业筛选 | MoodleUpcomingStore.upcoming | 我的、学习、完整列表、本地校园信息 |
| 本地文件读写 | ProtectedCampusCache | Moodle 摘要、Student 考试、Student 课程与个人预约缓存 |

## 行为约束

- 详情工厂只选择原有页面和 AppModel 已有的数据源，不新建缓存对象，也不内嵌 NavigationStack。原有父页面管理返回；下载弹窗仍由根页面提供独立导航和完成按钮。
- 详情外观统一标题模式及背景，不接管页面工具栏、布局边距或关闭方式。
- 作业卡保留原有详细／紧凑样式，统一标题规范化、截止日期及提交状态文本。相同截止时间以 URL 作为稳定排序依据，避免刷新后顺序跳动。
- 缓存读写只集中机械部分：读取大小限制、JSON 编解码、文件保护、排除备份与原子写入。原有文件路径、版本、校验、更新间隔及主动清理规则由原 Store 保留，旧文件原位可读。
- 编码失败不会覆盖上一份有效快照；损坏或超出各 Store 原有限制的文件不作为有效缓存加载。
- 修复我的页底栏重选：从服务中心详情返回根页时同时清除 serviceRoute，避免旧绑定在新导航栈中重新打开。

## 验证重点

1. 既有 Moodle／Student／预约缓存兼容，重启和清理行为保留。
2. 从摘要、设置和全局弹窗打开同一详情，工具栏和返回路径正确。
3. 服务中心详情下重选“我的”回根页，再次进入不残留旧路由。
4. 作业完成过滤、10 天范围、通知窗口等业务规则不变。
5. 原生详情浅／深色、列表／网格切换与主要页面布局无退化。
